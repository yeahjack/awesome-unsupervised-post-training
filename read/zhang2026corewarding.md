## When-to-Adapt audit

- **Auxiliary taxonomy:** `Timing Regime=Offline Corpus UPT`; `Visibility Scope=Pre-deployment corpus`.
- **Two-axis coding:** `Input Visibility=Offline`; `Update Persistence=Cumulative`; `Reset Boundary=Deployment Boundary`.

- **When the update is triggered:** updates fire during an offline RL stage before deployment; the basic unit is a group of rollouts per prompt batch.
- **Whose sample it serves:** the current rollout group's update serves subsequent training steps and the final deployed model, not the immediate inference of any single sample.
- **Whether parameters/state accumulate:** parameters accumulate across RL training; no per-sample reset.
- **Reset boundary:** it is an offline RL-style UPT schedule, not test-time arrival-by-arrival adaptation.

## 1. UPT Assignment Rationale

**Family II — Sample-Relation Supervision (trajectory-level consistency → contrastive agreement)**

Co-rewarding relies on no external ground-truth labels, human annotation, or external reward model. Its reward signal comes from sample-relation internal supervision over the model's own generated trajectories:

- **Co-rewarding-I (data side):** for the same question, generate a semantically equivalent paraphrase; sample multiple rollouts from each; use majority voting to produce a pseudo-label for the other side, and use the contrastive agreement (cross-consistency between original-question outputs and rephrased-question outputs) as the reward signal — a textbook trajectory-level contrastive agreement.
- **Co-rewarding-II (model side):** introduce a teacher model updated by EMA (exponential moving average); the teacher's rollouts are turned into pseudo-labels by majority voting to supervise the student (online policy). The teacher and student are decoupled along the time dimension, forming temporal-invariance relational supervision.

Both instantiations construct rewards from consistency / inconsistency among multiple trajectories generated by the model itself; no external verifier is required — fully consistent with the UPT definition.

## 2. Problem Addressed

Existing self-rewarding RL methods (e.g. Self-Certainty, Entropy minimization, Majority-Voting) suffer from severe **training collapse**:

- **Self-consistent illusion:** the reward signal is generated entirely from the current policy's single perspective; the model easily finds trivial solutions that hack the reward (e.g. entropy methods concentrate probability on a few tokens to produce repeated outputs; majority voting converges to a consistent but wrong answer).
- **Reward hacking:** performance rises rapidly early in training, then collapses; no sustained improvement.
- **Dependence on ground-truth labels:** traditional RLVR depends on high-quality external labels, limiting scaling.

Co-rewarding's core idea borrows from self-supervised learning (e.g. SimCLR, BYOL, DINO): introduce **complementary supervision** by adding a signal from "another perspective" to break the single-view feedback loop, achieving stable self-supervised RL training.

## 3. Method

### 3.1 Core philosophy: invariance beyond a single perspective

True reasoning ability should remain invariant across different data perspectives and across the time evolution of the model. Co-rewarding shifts the foundation of self-supervised RL from "suspect single-view feedback" to "cross-view invariance."

### 3.2 Two instantiations

#### Co-rewarding-I: Data Side (analogy-invariance)

1. For each original question x, use an LLM (Qwen3-32B) to produce a semantically equivalent rephrased version x'.
2. Sample G rollouts each from x and x'.
3. Run majority voting on x's rollouts to obtain pseudo-label y_v; do the same on x' to obtain y'_v.
4. **Cross supervision:** use y'_v as the reward standard for x's rollouts and y_v for x' 's rollouts.
5. Compute the advantage with the GRPO framework and optimize.

The objective is J = J_original(θ) + J_rephrased(θ), where the two terms supervise each other through swapped pseudo-labels.

#### Co-rewarding-II: Model Side (temporal invariance)

1. Maintain a reference teacher π_ref updated by EMA.
2. The teacher samples rollouts on the question; majority voting produces a pseudo-label.
3. Use the teacher's pseudo-label as the reward signal for the student (online policy).
4. Update the teacher dynamically via EMA: π_ref^(k) ← α^(k) · π_ref^(k-1) + (1 - α^(k)) · π_θ_old^(k).
5. α follows a cosine annealing schedule from α_start=0.99 to α_end=0.9999 (fast updates early, slow updates later).

This design resembles self-distillation (BYOL/DINO style): a slowly-updated teacher supervises a fast-moving student, breaking the on-policy feedback loop.

### 3.3 Implementation details

- Built on the GRPO optimization framework, implemented in VeRL.
- 4 × H100-80GB GPUs.
- Batch size 128; G = G̃ = 8 rollouts per question.
- AdamW optimizer, learning rate 3×10⁻⁶.

## 4. Datasets

### Training sets
- **MATH** (Hendrycks et al., 2021): 7,500 math problems.
- **DAPO-Math-17k** (Yu et al., 2025): about 14.1k math problems (the English DAPO-14k).
- **OpenRS** (Dang & Ngo, 2025): 7,000 math problems.

### Evaluation benchmarks
- **Math reasoning:** MATH500, GSM8K, AMC.
- **Code generation:** LiveCodeBench (release_v6), CRUX.
- **Instruction following:** IFEval.
- **Multi-task ability:** MMLU-Pro.

### Base models
- Qwen2.5 series: 3B, 7B.
- Qwen3 series: 1.7B-Base, 4B-Base, 8B-Base.
- Llama3 series: Llama-3.2-3B-Instruct.

## 5. Evaluation metrics and main results

### Metric
- **Pass@1:** the main metric — probability of being correct on a single sample.

### Main results

**Advantage over self-rewarding baselines:**
- Co-rewarding-I averages **+3.46%** over the best baseline on three math benchmarks (Table 1, MATH training set).
- Co-rewarding-II averages **+7.29%** on the DAPO-14k training set (Table 2).
- Overall, beats all self-rewarding baselines by **+3.31%** on average.

**Surpassing GT-Reward:**
- On GSM8K, both Co-rewarding variants beat RLVR with ground-truth labels, combining for a relative gain of +2.94% (Table 1).
- Co-rewarding-II + Qwen3-8B-Base reaches **94.01% Pass@1** on GSM8K, substantially higher than GT-Reward.

**Training stability:**
- The three self-rewarding baselines (Self-Certainty, Entropy, Majority-Voting) all show training collapse.
- Co-rewarding-I is stable on MATH but still collapses on DAPO-14k (DAPO-14k questions lack rich background descriptions, limiting the effectiveness of rephrasing).
- **Co-rewarding-II remains stable across all datasets** with no collapse.

**Generalization:**
- Trained only on math data, but still improves on code benchmarks (LiveCodeBench, CRUX).
- Beats self-rewarding baselines on 12 of 14 categories of MMLU-Pro.
- Instruction-following ability on IFEval is preserved.

### Ablation results (Table 3)
- Co-rewarding-I: removing cross-supervision (using only the original or only the rephrased side) hurts performance — cross supervision is key.
- Co-rewarding-II: removing the EMA-updated reference teacher causes clear degradation — the teacher's dynamic update is critical for pseudo-label quality.
