## When-to-Adapt audit

- **Auxiliary taxonomy:** `Timing Regime=Offline Corpus UPT`; `Visibility Scope=Pre-deployment corpus`.
- **Two-axis encoding:** `Input Visibility=Offline`; `Update Persistence=Cumulative`; `Reset Boundary=Deployment Boundary`.

- **When the update is triggered:** updates happen during the pre-deployment preference-optimization stage; the basic unit is model-generated chosen/rejected pairs.
- **Serving the current sample or future ones:** updates on the current pair batch serve subsequent training and the final deployed model, not the immediate inference of the current sample.
- **Whether parameters/state accumulate:** parameters accumulate across training epochs / iterations with no sample-level reset.
- **Reset boundary:** this is offline pair-based post-training, not online TTA.

## 1. UPT Assignment Rationale
**Family III — Self-Generated Target Bootstrapping (internally generated preference pairs)**

LongPO fully matches the UPT definition: it **does not rely on any human-annotated long-context data** and instead uses the model's existing short-context capability to automatically generate short-to-long preference data — preference pairs from responses generated by the same instruction on a long context vs. a compressed short context. These preference pairs are entirely model-internal (short-context response → chosen, long-context response → rejected), and training proceeds with a DPO-style preference-optimization objective. No external reward model or human feedback — a textbook internally-generated-preference-pair route.

---

## 2. Problem Addressed

LongPO addresses: **how to effectively transfer a short-context LLM's capability to long-context settings without any human long-context annotation, while preserving short-context performance**.

Concretely, existing long-context alignment faces two challenges:
1. **Data scarcity:** as context length grows, human annotation becomes impractical and unreliable; synthesizing data from advanced LLMs is unscalable; simply concatenating short-context data works poorly.
2. **Performance balance:** long-context alignment often badly degrades short-context performance. For example, the LLaMA-3.1 series uses only 0.1% long-context data during alignment, limiting how thoroughly long-context alignment can be done.

The paper observes that even GPT-4, which is exceptional in short context, performs poorly in long context (GPT-4-128K scores only 34.81 on ∞Bench — even below LLaMA-3.1-8B), revealing untapped long-context potential.

## 3. Method

### 3.1 Core idea: short-to-long preference

LongPO's core hypothesis: **capabilities learned in short-context pretraining and alignment can effectively transfer to long context without external guidance**.

Given a long input $x_L = [C_L; I_L]$ (long document $C_L$ + instruction $I_L$) and an instruction-relevant short context extracted from $C_L$, $C_S = F(C_L, I_L)$, the model generates two responses:
- **Chosen response:** $y_S \sim \pi_S(y \mid x_S)$, on the short context $x_S = [C_S; I_L]$ (the short-context model handles this well — high quality)
- **Rejected response:** $y_L \sim \pi_S(y \mid x_L)$, on the long context $x_L$ (the short-context model handles this poorly — low quality)

Define the short-to-long preference distribution (Bradley–Terry):

$$p_{SL}(y_S \succ y_L \mid x_L) = \sigma(r(x_L, y_S) - r(x_L, y_L))$$

LongPO objective:

$$\mathcal{L}_{\text{LongPO}}(\pi_\theta; \pi_{ref}) = -\mathbb{E}_{(x_S, x_L, y_S, y_L) \sim D_{SL}} [\sigma(r_\theta(x_L, y_S) - r_\theta(x_L, y_L))]$$

### 3.2 Short-to-long constraint

Long-context alignment often degrades short-context performance. The standard DPO/RLHF KL constraint $\beta D_{KL}[\pi_\theta(y|x_L) \| \pi_{ref}(y|x_L)]$ uses a reference model that itself struggles with long context — an inappropriate constraint.

LongPO proposes an improved **short-to-long KL constraint**:

$$C' = \beta D_{KL}[\pi_\theta(y \mid x_L) \| \pi_S(y \mid x_S)]$$

i.e., constrain the policy's long-context output distribution to stay close to the short-context reference model's distribution on a short context carrying the same core information.

This yields LongPO's refined reward function:

$$r_\theta^{\text{LongPO}}(x_L, y) = \beta \log \frac{\pi_\theta(y \mid x_L)}{\pi_S(y \mid x_S)} + \beta \log Z(x_L, x_S)$$

The final LongPO objective:

$$\mathcal{L}_{\text{LongPO}}(\pi_\theta; \pi_S) = -\mathbb{E}_{D_{SL}} \left[\log \sigma \left(\beta \log \frac{\pi_\theta(y_S \mid x_L)}{\pi_S(y_S \mid x_S)} - \beta \log \frac{\pi_\theta(y_L \mid x_L)}{\pi_S(y_L \mid x_S)} \right)\right]$$

Key difference from standard DPO: the reference model in the denominator is conditioned on the **short context** $x_S$ via $\pi_S(\cdot|x_S)$, not on the long context $x_L$.

### 3.3 Self-evolving pipeline

**Initialization:** only need an aligned short-context LLM $\pi_S$ and a long-context plain corpus.

**Preference-data construction** (two steps):
1. **Instruction generation:** for each long document $C_L$, randomly sample a short chunk $C_S$ and use $\pi_S$ via Self-Instruct to generate an instruction pool, randomly selecting one $I_L$.
2. **Response generation:** use $I_L$ to generate a chosen response $y_S$ on the short context $x_S$ and a rejected response $y_L$ on the long context $x_L$.

**Multi-turn LongPO:** since one long document contains multiple chunks, collect multiple instruction-response triples to form a multi-turn dataset, aggregating probabilities:

$$\mathcal{L}_{\text{LongPO}}^{MT} = -\mathbb{E}_{\hat{D}_{SL}} \left[\log \sigma \left(\beta \log \frac{\sum_{i=1}^n \pi_\theta(y_{Si} \mid x_L)}{\sum_{i=1}^n \pi_S(y_{Si} \mid x_{Si})} - \beta \log \frac{\sum_{i=1}^n \pi_\theta(y_{Li} \mid x_L)}{\sum_{i=1}^n \pi_S(y_{Li} \mid x_{Si})} \right)\right]$$

**Final training objective** adds NLL loss for stability:

$$\mathcal{L}_\theta = \lambda \cdot \mathcal{L}_{\text{LongPO}}^{MT}(\pi_\theta; \pi_S) + \mathcal{L}_{\text{NLL}}(\pi_\theta; S_L)$$

with $S_L = [x_L; \{I_{Li}; y_{Si}\}_{i=1}^n]$ being the long context concatenated with chosen responses.

**Iterative extension:** LongPO iteratively extends context length (32K → 128K → 256K → 512K); the trained model from each round serves as the next round's "short-context LLM".

### 3.4 Training details

- Optimizer: Adam, learning rate 5e-7
- $\beta = 0.1$ (DPO margin), $\lambda = 0.01$ (NLL weight)
- RoPE $\theta = 1 \times 10^7$, batch size = 8
- Deepspeed-Ulysses sequence parallelism, Flash Attention

### Key findings

1. **LongPO substantially beats SFT and DPO:** on the same model and data, LongPO outperforms SFT and DPO on long-context tasks by **10–20+ points** (∞Bench: 39.27 vs. SFT 30.03 / DPO 25.56) and also leads on RULER (86.06 vs. 73.15 / 65.62).

2. **Short-context performance fully preserved:** LongPO maintains 59.99 on MMLU (base model 59.15), whereas SFT and DPO degrade short-context performance by **14–25 points**. Credit goes to the short-to-long KL constraint.

3. **Beating GPT-4-128K:** Mistral-7B-LongPO-128K scores **39.27** on ∞Bench, beating GPT-4-128K's **34.81** with far fewer parameters (7B vs. ~1.8T) — even the most advanced LLMs have untapped long-context potential.

4. **Iterative extension works:** going 128K → 256K → 512K iteratively keeps improving long-context performance (∞Bench: 39.27 → 39.65 → 41.21) with minimal short-context impact.

5. **Clear lead on En.QA:** on complex book-length free-form QA, LongPO beats GLM-4-9B and GLM-4-9B-1M by **>10 points**, showing human annotation cannot cover complex long-context tasks.

6. **Ablations:**
   - **Short-to-long preference is effective:** LongPO consistently beats SFT-Chosen and SFT-Rejected, showing explicit preference learning is more effective than implicit preference.
   - **Short-to-long constraint is critical:** removing it (reducing to DPO) badly hurts both long and short context; short-context ability drops sharply in early training.
   - **NLL loss matters:** removing NLL slows long-context convergence, indicating NLL is critical for stable long-context training without continual pretraining.

7. **Cross-model generalization:** LongPO also works on Qwen2.5-7B-Instruct (∞Bench: 27.12 → 40.48, +13.36 points).
